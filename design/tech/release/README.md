# Release

## Summary

How a version of the game reaches players: the version number, the application icon, what each
download carries, the release notes and the CI release job. The first release is `v0.1`, Acts
1–2 (the roadmap's M6). Accepted by the user in concept round 35 (2026-10-12); the final title
and the repository's name (Q11) and the tag itself wait until next week.

## Design

### Version

- One version for the whole build: `version=0.1.0` in `gradle.properties` (semantic versioning;
  Acts 1–2 is 0.1, each further act release raises the minor number, fixes the patch number).
- The build writes it into `vanguard/version.properties` on the class path (the desktop module's
  `versionResource` task), the jar manifest (`Implementation-Version`), the macOS plist
  (`CFBundleShortVersionString`, `CFBundleVersion`), the zip names and the bundle README.
- `terran-vanguard --version` prints `Terran Vanguard 0.1.0` and exits; every start logs the
  same line first.
- The title and the main menu show `v0.1` (major.minor) small in the bottom-left corner: the
  launcher reads the resource and passes it to the game (M6 part B, see the
  [main menu](../../ui/main-menu/README.md#decisions)).
- The release tag is `v0.1` (`v<major>.<minor>`, or the full `v0.1.1` for a fix release); the
  CI release job fails when the tag does not match `gradle.properties`.

### Application icon

The AF-12 [Stormhawk](../../player/ship/README.md) from above, rendered from the model of its
production sprite (level frame, no pods) at icon resolution, on a dark navy tile with a rounded
blue trim in the [title logo](../../ui/main-menu/README.md)'s steel blue and a faint glow behind
the ship. One 1024 px master; every size is drawn from it, the sizes up to 48 px with a mild
unsharp mask.

| Use | File | Sizes |
|---|---|---|
| Window icon (Linux, Windows; macOS has none) | `assets/icon/icon-<size>.png` | 16, 32, 48, 64, 128, 256 |
| Windows exe (Construo `icon`) | `desktop/icons/terran-vanguard.ico` | 16–256 |
| macOS app (Construo `macIcon`) | `desktop/icons/terran-vanguard.icns` | 16–1024 |

Generated by `tools/art/app_icon.py` (also the review sheet below).

### Bundles

Construo cross-builds four zips on Linux, each with a trimmed Java 21 runtime:
`terran-vanguard-<version>-<target>.zip` for `linuxX64`, `winX64`, `macX64` and `macM1`. Each
unpacks into a folder `terran-vanguard-<version>/` that holds the game (`terran-vanguard`,
`terran-vanguard.exe` or `Terran Vanguard.app`) and three files for the player:

- `README.txt` (`desktop/bundle/README.txt`, the version filled in): how to start the game on
  each OS, including the steps past SmartScreen and Gatekeeper for the unsigned game, the
  controls, where the settings, saves and screenshots live, that this is Acts 1–2 of 7, and
  the licence pointers;
- `LICENSE.txt` (the repository's `LICENSE`);
- `CREDITS.md` (the third-party files with their licences).

Licence (Q13, the user's decision of 2026-10-12): the game's own code, art, music and voices are
open source under the Apache License 2.0, the repository's `LICENSE`; third-party assets keep
their own licences, listed in `CREDITS.md`. The bundle README, the release notes and the credits
roll say so.

On macOS they sit beside the app, not inside it (Construo puts package files next to the
executable, so the macOS zips are rewritten by the `package<Target>Docs` tasks).

Measured on 2026-10-12 (build of commit 50d4dce plus this step's changes):

| Target | Zip | Unpacked |
|---|---|---|
| linuxX64 | 152.2 MB | 197.6 MB |
| winX64 | 148.6 MB | 184.8 MB |
| macX64 | 149.8 MB | 190.5 MB |
| macM1 | 148.6 MB | 188.5 MB |

The fat jar is 124 MB of each (the atlases and the music). The Linux bundle, unpacked with no
JDK on the `PATH`, ran a 10 s `--bench` under Xvfb (llvmpipe, full screen 1920×1080) at 322 fps
with a peak resident set of 1.74 GB.

### Signing

Not signed (concept question Q8, a; accepted by the user in round 35): an Apple Developer ID and a Windows code-signing
certificate cost money every year. The release notes and the bundle README explain the
SmartScreen "More info → Run anyway" step and, for macOS, Open from the context menu, "Open
Anyway" in Privacy & Security, or `xattr -dr com.apple.quarantine` when macOS reports the
unsigned app as damaged. Whether a zipped, unsigned arm64 app opens after the `xattr` step or
needs an ad-hoc `codesign --sign -` is not verified: it needs the user's Mac.

### Release notes

[release-notes.md](release-notes.md) is the template `gh release create --notes-file` uses; the
CI job fills in `@version@` and `@tag@`.

### CI release job

On a `v*` tag (`.github/workflows/ci.yml`, job `release`, after `check` and `smoke`): check the
tag against the version, build the four bundles, unpack the Linux zip and start it with no JDK on
the `PATH` (`--version`, then `--bench 5` under `xvfb-run` with software OpenGL), then create the
release with the four zips and the filled-in notes.

## Decisions

- 2026-10-12: M6 part C built with the defaults of Q8 (unsigned, with the steps in the notes and
  the README), Q9 (the Stormhawk icon), Q10 (0.1.0, tag `v0.1`) and Q15 (README, licence and
  credits in each bundle); pending the user's review in concept round 35.
- 2026-10-12: The zips unpack into a folder of their own (`terran-vanguard-<version>/`) instead
  of spilling the game's files into the folder they are unpacked in; pending the user's review.
- 2026-10-12: The licence ships as `LICENSE.txt` (the repository's `LICENSE`) so it opens with a
  double click on Windows; pending the user's review.
- 2026-10-12: `fatJar` now depends on the runtime class path explicitly: from a clean build the
  packaging failed, as the mapped class path dropped the jar tasks' dependencies.
- 2026-10-12 (user, round 35): accepted as built: Q8 (unsigned; R.5, the arm64 app on a real Mac,
  stays open), Q10 (0.1.0, tag `v0.1`), Q15 (the bundle contents), the build choices C.1 (a)–(b),
  the release notes (C.2) and the bundle sizes (C.3); Q9: the application icon
  (`app-icon-r35-a`) approved as **final**, `art: final`. Q13: the game's own art, music and voices
  are Apache-2.0 like the code. Q11 (title and repository name) and R.4 (merge and tag: not
  possible until the commits can be signed) stay open until next week. `design: approved`.
